# gemini-web2api 接入指南（DSH 用）

> 作用：把 Google Gemini **网页版**（gemini.google.com）转成本地 OpenAI 兼容 API，
> DSH / Cherry Studio / 任意 OpenAI 客户端都可以直接调用，**不需要 Google API Key**。

---

## 一、当前状态（2026-09-05）

✅ 已在本机跑通，**匿名模式即可对话**（本机 Clash 代理 127.0.0.1:7890 已被自动用作出口）

```
DSH ──(OpenAI API)──> http://127.0.0.1:8081/v1 ──> gemini-web2api ──> gemini.google.com（经日本出口）
```

| 项 | 值 |
|---|---|
| Base URL | `http://127.0.0.1:8081/v1` |
| API Key | `sk-gemini` |
| 协议 | OpenAI Chat Completions（含 SSE 流式） |

**匿名模式可用的模型**（会走网页免费额度）：
- `gemini-3.7-flash` / `gemini-3.6-flash` / `gemini-3.5-flash`
- `gemini-3.5-flash-thinking`（思考/长输出 ~20k 字符）
- `gemini-3.5-flash-thinking-lite` / `gemini-flash-lite` / `gemini-auto`

> ⚠️ `gemini-3.1-pro` 需要 **Pro 账号 cookie** 才走真实 Pro 路由，否则静默降级为 Flash。

## 三、⚠️ Pro 路由还差关键一步：完整 cookie

实测确认（诊断脚本读上游 `slot39`，权威字段）：**当前 cookie 请求 3.1-pro 被上游拒绝
（返回 `cf41b0e0dd7d53e5` 拒绝标记），实际跑的是 3.5 Flash-Lite**。网页版正常是因为浏览器
会自动续期短命 cookie，反代只会重放冻结快照。

需要**重新导出完整 cookie**，至少包含：
- ✅ 已有的：`SID` `HSID` `SSID` `APISID` `SAPISID` `__Secure-1PSID`
- ❌ 缺失的关键项（必补）：`__Secure-1PSIDTS`（最重要）、`__Secure-3PSIDTS`、`SIDCC`、`__Secure-1PSIDCC`

### ✅ 首选方案：用项目自带的浏览器扩展一键导出（最省事、最安全）

项目自带 `gemini-cookie-sync-extension/`，能在浏览器里一键读取当前 Gemini 登录会话的
**全部 cookie（含 httpOnly 的 `__Secure-*`）+ 自动提取 XSRF (SNlM0e) + gemini_bl + auth_user**，
导出 `gemini-auth.json`。Cookie 全程不离开本机，比手动复制既快又全。

**安装步骤：**
1. Chrome 打开 `chrome://extensions` → 右上角开启 **开发者模式**
2. 点 **"加载已解压的扩展程序"** → 选 `D:\CodePackage\DSP\gemini-web2api\gemini-cookie-sync-extension` 文件夹
3. 打开 [https://gemini.google.com/app](https://gemini.google.com/app)，**登录你的 Pro 账号**，刷新页面
4. 点扩展图标 → **Inspect session**（应显示 "Session and XSRF are ready for export"）
5. 点 **Export gemini-auth.json** → 保存到 `D:\CodePackage\DSP\gemini-web2api\gemini-auth.json`

**接入服务：** 编辑 `config.json`，把 `cookie_file` 改成：
```json
"cookie_file": "D:/CodePackage/DSP/gemini-web2api/gemini-auth.json",
```
> 服务代码已改造：会自动从 `gemini-auth.json` 读取 cookie + xsrf_token + gemini_bl + auth_user
> 注入配置，无需手动改 xsrf/bl。改完 `manage.ps1 stop` 再 `start` 生效。

> TS 系列 cookie 约每 30 分钟~数小时轮换，过期后 Pro 会静默降级；届时重新导一次即可
> （扩展会重新抓最新值）。

### 备选方案：手动复制完整 cookie

Chrome 打开 `gemini.google.com`（已登录 Pro）→ F12 → Application → Cookies →
`https://gemini.google.com`，把**所有** cookie 按 `名=值; 名=值; ...` 整行粘贴进 `cookie.txt`，
重点确保含 `__Secure-1PSIDTS` 等缺失项。

## 四、日常管理命令

在 `D:\CodePackage\DSP\gemini-web2api` 目录下：

```powershell
powershell -File manage.ps1 start    # 启动（后台运行，日志 server.log）
powershell -File manage.ps1 status   # 查看状态
powershell -File manage.ps1 test     # 跑一次对话测试
powershell -File manage.ps1 stop     # 停止
powershell -File manage.ps1 log      # 看最近日志
```

也可以直接双击 `start.bat`（前台运行，关窗即停）。

## 五、DSH 配置

在 DSH 的 Provider / 模型配置里新增一个 Custom Provider：

| 字段 | 值 |
|---|---|
| Provider 名称 | `gemini-web` |
| Base URL | `http://127.0.0.1:8081/v1` |
| API Key | `sk-gemini` |
| 协议 | OpenAI-compatible |
| 模型名 | `gemini-3.5-flash-thinking`（或上面列表任一） |

> 让 DSH 调用前，先确保服务已启动（`manage.ps1 status` 显示运行中）。

## 七、换日本节点（可选）

当前走的是本机 Clash `127.0.0.1:7890`。如果你要**固定指定某个出口**，改 `config.json`：

```json
"proxy": "http://你的日本代理地址:端口"
```

改完 `manage.ps1 restart` 生效（本脚本无 restart，先 stop 再 start）。

## 八、注意事项

- 这是**逆向 Gemini 网页接口**的非官方方案，Google 改版后可能失效；本项目持续更新，出问题先看 Issue #82。
- 匿名模式有网页频次限制；接 cookie 后额度更高、可用 Pro 模型。
- 若大量调用触发风控，Google 可能要求人机验证——属正常现象。
